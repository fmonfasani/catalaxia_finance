## FASE B — Qué se verifica de F-054

**Pregunta:** ¿puede procesarse más de una empresa sin que la provenance de una
apunte a hechos de otra?

| # | control | criterio de PASS |
|---|---|---|
| 1.1 | **todos** los elementos de `source_fact_ids` (no sólo el primero) resuelven a `parsed.facts` del **mismo CIK** | 0 ajenos |
| 1.2 | ningún puntero colgado | 0 colgados |
| 2.1 | los rangos de `fact_id` de cada emisor no se solapan | 0 solapes |
| 2.2 | la secuencia no fue reiniciada | `last_value ≥ max(fact_id)` |
| 2.3 | `fact_id` es único | 0 repetidos |
| 3.1 | ningún hecho derivado cita un `accession` distinto del suyo | 0 |
| 3.2 | el `qname` citado coincide | 0 |
| 4.1 | la corrida S02 elegida por CIK no contiene otro emisor | 0 |

**Mutación exigida:** revertir el borrado a `DELETE FROM {table}` +
`setval(…,1,false)` en base descartable y demostrar que la corrupción
**reaparece**; restaurar y demostrar que **no**. Un control que sólo sabe
aprobar no prueba nada.

**Independencia del orden:** procesar A→B y B→A debe dar el mismo aislamiento.

## FASE C — Qué se verifica de F-055

**Pregunta:** ¿se sigue perdiendo algún hecho por contextos declarados
contradictorios que no lo son?

| # | control | criterio de PASS |
|---|---|---|
| 5.1 | contextos contradictorios bajo la regla canónica | 0 |
| 5.2 | la comparación ingenua marcaba falsos positivos | > 0 (si no, la corrección no corrigió nada) |
| 6.1 | hechos que dependen de un contexto descartable | 0 |
| **6.2** | **`derived` tiene exactamente un hecho por grupo canónico `(cik, accession, qname, context_id, unit_ref)` de `parsed`** | diferencia = 0 |
| 6.3 | existen emisores con doble representación (inline + instancia) | > 0 |
| 6.4 | `n_fuentes` declara cuántas fuentes se colapsaron | ≥ 1 siempre |

**6.2 es el control central.** Prueba conservación sin depender de ningún conteo
declarado por el implementador: si la deduplicación pierde algo, la diferencia
es distinta de cero.

**Mutación exigida:** volver a `dimensions::text` y demostrar que reaparecen los
contradictorios y la pérdida.

**Falso negativo:** inyectar un contexto **genuinamente** contradictorio (mismo
`context_id`, período distinto) y verificar que la regla canónica **lo sigue
detectando**. Una canonización que absorbe todo sería peor que el defecto.

## Reglas de la auditoría

- La base homologada **no se modifica**. Toda mutación va en base descartable.
- No se aceptan como evidencia: logs del implementador, tests del implementador,
  documentos que declaran PASS, conteos aislados.
- Cada invariante se reconstruye con SQL propio, escrito desde el contrato.
- Un control que pasa por ausencia de excepción no cuenta.
