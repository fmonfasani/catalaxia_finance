# CONTRATO R4 — CAPA 11: CERTIFICACIÓN INDEPENDIENTE
Estado: **APPROVED → IMPLEMENTAR** (activación INFORMATIVA) · Origen: ficha P1-R4 + hallazgo nº1 de 04_PIPELINE_REAL
(no hay capa 11 real). Evidencia verificada 2026-09-06.

JSON solo artefacto de evidencia; NO migrar criterio de 40_certificar (mundos separados); activación inicial INFORMATIVA.

## 1. OBJETIVO

Crear la capa 11 de certificación **independiente** del cálculo y de la validación:
`VALIDACIÓN (Capa 10) → CERTIFICACIÓN (Capa 11) → PUBLICACIÓN (Capa 12)`.
C11 LEE `engine.runs` + `engine.stage_runs` (+ `engine.checkpoints` cuando corresponda), evalúa resultados ya
producidos y emite un **acta de certificación** en `engine.certifications`. NO calcula datos, NO modifica tablas
de cálculo, NO reemplaza VALIDACIÓN. Regla de arquitectura que satisface: **VALIDACIÓN ≠ CERTIFICACIÓN** (harness 1.10/1.11).

## 2. INVARIANTES (lo que NO puede pasar)

- INV1 — C11 es READ-ONLY sobre tablas de cálculo (capas 1–10). No INSERT/UPDATE en datos. Solo escribe su acta.
- INV2 — C11 NO se acopla a `validar_suite`/`f6_sec`/`40_certificar` como autoridad: puede leer sus resultados, nunca delegarles el sello.
- INV3 — Veredicto determinista y reproducible: mismas `stage_runs` → mismo `cert_hash`.
- INV4 — `gate_status=BLOCK` en cualquier etapa → certificación NEGADA (no emitida). `WARNING` → emitida con observaciones. `PASS` → limpia.
- INV5 — La salida PRIMARIA es la tabla PostgreSQL `engine.certifications`. JSON permitido SOLO como artefacto de evidencia, no como fuente primaria.
- INV6 — Las certificaciones son inmutables tras emitirse (un `cert_id` por `run_id`; re-ejecución idempotente, sin reescritura del acta).
- INV7 — C11 inicialmente **INFORMATIVA**: NO bloquea API ni PUBLICACIÓN.

## 4. DISEÑO (para fase EXEC)

**4.1 Nuevo módulo — `scripts/engine/c11_certificar.py`**
- Lee `engine.runs` (último run por mode, o `--run_id`), `engine.stage_runs` con `gate_status`/`gate_reasons`.
  Lee `engine.checkpoints` cuando corresponda (input_hash/code_version/contract_version como contexto del acta).
- NO ejecuta cálculo; NO toca tablas de datos.
- Algoritmo de veredicto:
  - `BLOCK` en ≥1 stage → `NEGADA` (reason: stages×gate_status)
  - `elsif` algún `WARNING` → `CERTIFICADA_CON_OBSERVACIONES` (lista)
  - `elsif` todo `PASS` → `CERTIFICADA`
- Escribe acta en `engine.certifications`. Emitir además artefacto JSON de evidencia (opcional, no primario).

**4.2 Migración — `migrations/engine/034_c11_certifications.sql`**

> **Numeración corregida en ejecución (2026-09-06).** El contrato original
> proponía `002_c11_certifications.sql`, pero `002_s01_identity.sql` ya existe
> y está aplicada. F-049: el runner es el único dueño del registro y el orden
> de aplicación es por nombre; no se altera el historial. Se adopta el
> consecutivo real posterior a `033_ratio_inputs_solo_si_calculado.sql`:
> **`034_c11_certifications.sql`**. Ver `docs/review/R4_CAPA11_EVIDENCIA.md`.
```sql
CREATE TABLE IF NOT EXISTS engine.certifications (
    cert_id TEXT PRIMARY KEY,
    run_id TEXT NOT NULL REFERENCES engine.runs(run_id),
    pipeline_version TEXT NOT NULL,
    veredicto TEXT NOT NULL CHECK (veredicto IN ('CERTIFICADA','CERTIFICADA_CON_OBSERVACIONES','NEGADA')),
    stages_total INT NOT NULL, stages_pass INT NOT NULL,
    stages_warn INT NOT NULL, stages_block INT NOT NULL,
    cert_hash TEXT NOT NULL,
    acta JSONB NOT NULL DEFAULT '{}'::jsonb,
    generado_por TEXT NOT NULL,
    generado_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS ix_cert_run ON engine.certifications (run_id);
CREATE UNIQUE INDEX IF NOT EXISTS ux_cert_run ON engine.certifications (run_id);
```
